# Replication plan: what to build, run, and compare against the SABench paper

Written 2026-09-14. Data status is in `PAPER_DATA_ISOLATION_AUDIT.md` and
`paper_replication_summary.md`: 236 of 240 slices rebuilt with matching cells
(100 exact, 136 near), Data79 within 4%, Data234 with an unknown hemisphere
cut, Data239 dropped (data-access restriction), Data240 pending the hemisphere
sample. This plan says what has to happen next so that agent results can be put
next to the paper's numbers, and how much of the paper each step covers.

## 1. The three kinds of comparison we can make

| Kind | What the paper published | What we need on our side | Where it applies |
| --- | --- | --- | --- |
| Direct score comparison | per-method metric values for a named task | same slices, same metric code, same unit (pair or slice) | DLPFC and MHPR gene+landmark (Fig. 2a, 2b), DLPFC and MHPR rotation/crop (Fig. 3), MOB genes (Fig. 5b), Flysta3D and MLN MAE (Fig. 5f, 5g) |
| Success matrix | ran or failed, per method per pair | the same pairs, a run record per method and per agent | AMBC cross-platform (Fig. 5d) |
| Aggregate rank comparison | one rank per method per metric, averaged over datasets, for the NGS group (Data1-4, 10-12, 16-31, 32-35) and the imaging group (Data5-9, 36-41, 45-77) | per-dataset scores for every method, which the paper did not publish, so we must run the 11 methods ourselves on the same 9 datasets, rank them the paper's way, and check our rank vectors against MOESM9 before inserting agents | Fig. 4b, Supp. Fig. 12 |

The aggregate comparison is the one that covers the most of the paper (71 of
the 240 slices, 9 datasets) and it is feasible because all 71 slices are now
rebuilt with the paper's cells. Its cost is that the reference is generated by
us, so step 3 below includes a check that our method ranking reproduces the
published ranking before any agent is placed on it.

## 5. Caveats to state in any write-up

- DLPFC inputs: the paper's slices were randomly rigid-transformed and only
  two of the four transformed files are public, so initial pose differs for
  151675 and 151676. Methods that are pose-sensitive (PASTE without pi0,
  STalign, SLAT) may score differently for that reason alone.
- Data79: our MOB Slide-seqV2 has 21,724 beads versus the paper's 20,835; the
  gene-based metrics use grid aggregation, so a 4% bead difference is a small
  effect but not zero.
- Data234 Xenium: the paper's hemisphere cut is unknown; the pair rows
  involving Xenium in Fig. 5d are the least exact.
- STARmap+: the paper's object stored a dense normalized matrix (sparsity 0),
  ours stores counts; gene-based metrics must be computed after the same
  normalization.
- Aggregate ranks: the paper assigned failed runs the worst rank; we must do
  the same, and record failures explicitly.
- GPU methods on a Mac: GPSA, CAST, STAIR, SANTO, STAligner may be slow or
  fail on CPU; if the rank check in A1 fails for those methods only, run them
  on a Linux GPU machine before drawing conclusions.

## 6. Suggested order

1. B1 scoring mode and B2 runner for the CPU-friendly methods (PASTE family,
   SPACEL, spateo), then R1 on the 9 datasets and A1. If tau against MOESM9 is
   high for those methods, the pipeline is validated and everything else is
   incremental.
2. B3 sweep tasks and R4, because MOESM8 is the richest published reference
   (35 levels x 24 columns) and the tasks are cheap.
3. B4, B5, B6, then R5 to R7 and A5 to A7.
4. R3 reruns on the rebuilt tasks and A2 placement.
5. B8 only if Fig. 2e is wanted.
