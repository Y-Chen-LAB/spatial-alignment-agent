# Paper data isolation audit (SABench, Nat. Comput. Sci. 2026, s43588-026-00977)

Written 2026-09-14. This note answers three questions about the SABench paper
that the spatial-alignment suite is built from.

1. For every figure in the paper, which slices were plotted, and do we hold
   those exact slices locally?
2. How much of the paper's 295-task benchmark do our 40 tasks cover?
3. Which per-method paper results exist in any public artifact, so that we can
   compare an agent's score against the paper's methods?

The short answers are in the next section. Reproducible evidence is in
`paper_slice_isolation_status.csv` (one row per paper slice, generated by
`scripts/audit_paper_slice_isolation.py`).

## Summary

The Zenodo record 18605715 is only the code archive. It holds one file,
`SABench.zip` (409,873,281 bytes, md5 `7a9bc923e8a20bba2eb105dc0685d52e`,
verified against our local copy). The zip contains the method wrappers, the
metric code, the plotting notebooks, and the tutorial data for DLPFC (4 slices)
and BCA Xenium (2 slices). It does not contain the other 234 processed slices or
any alignment results. The per-method numbers that back the figures come from
the Springer supplementary files (MOESM4 to MOESM10), which we already
downloaded and unpacked into `references/paper_source_data/s43588-026-00977/`.

The paper's own slice inventory (Source Data Fig. 1c, 240 rows with file name,
n_obs, n_var) lets us check every slice. Before today's fixes our local files
were 58 exact, 19 near (within 2% of the paper's cell count), 149 same source
but different filter, 2 different source, and 12 missing. After the fixes in
section 7 (MHPR, MOp, and Visium HD rebuilt from raw files already on disk) the
table is 91 exact, 9 near, 129 different filter (all WMB, which has no published
per-method numbers), 1 different source (the Xenium hemisphere crop), and 10
missing.

Our 40 tasks cover 215 of the paper's 260 real slice pairs at the family level,
but two of those families (WMB, MHPR) are currently built on the wrong cells, and
the 35 simulated perturbation pairs exist only as one hidden grid task (sa-002).
The 45 missing real pairs are 41 of the 45 AMBC cross-platform pairs, 2 MBRM
pairs, the MOB pair, and the BCA Visium to Xenium pair.

Per-method paper results exist for only five dataset families. Everything else
in Fig. 4b is published as a rank averaged over datasets, and the raw
per-dataset scores are not in any public file. We also have not run the 11 paper
methods ourselves on our tasks, so for 33 of 40 tasks there is no per-method
reference at all.

Recipe for MHPR (Data5-9). The paper file names `MERFISH_0.04` to
`MERFISH_0.24` are Animal_ID 1 at Bregma -0.04, -0.09, -0.14, -0.19, -0.24 with
`Cell_class == "Ambiguous"` removed. With that filter the Dryad CSV we hold
gives 5488, 5557, 5926, 5803, 5543 cells, which equals the paper 5/5. The paper's
155 genes are the 156 non-blank columns minus `Fos`, which is all NaN in this
release. Our current `sa-009` was compiled from Bregma -0.14, -0.09, -0.04,
+0.01, +0.06 with all cells kept, so it is a different task from the paper's
Fig. 2b even though the family name matches. `scripts/compile_mhpr_csv.py`
already accepts `--bregmas`; it needs an option to drop Ambiguous cells and the
`Fos` column.

Recipe for WMB (Data99-227). The paper cell set is the cellxgene file
`sabench_full/Data99-227_WMB/wmb_animal1_local.h5ad` restricted to cells where
`obs.ccf_region_name` and `obs.major_brain_region` are both not NaN, for
sections C57BL6J-1.010 to 1.141. That filter reproduces the paper cell count for
all 129 sections. Our `sa-023` compile intersected the Allen ABC raw matrix with
the CCF coordinate table instead, which keeps about 2.6M cells versus the paper's
3.7M. The gene count is 1,120 in cellxgene versus 1,122 in the paper, so the paper
probably took genes from the ABC raw matrix and cells from the cellxgene-style
metadata. Either way the cell set is now reproducible.

Recipe for MOp (Data45-77). The paper slices are every cell listed in
`cell_labels.csv` (which is the obs of `counts.h5ad`, 280,186 cells) grouped by
`slice_id` for mouse 1, in the slice order 1, 10, 21, 31, 40, 50, 62, 71, 81,
91, 102, 112, 122, 131, 153, 162, 170, 180, 190, 200, 201, 212, 221, 232, 241,
251, 260, 271, 283, 291, 301, 313, 326. That reproduces the paper count for all
33 slices. Our compile dropped cells whose ID did not join to a segmentation
boundary row, which lost 1 to 3% of cells on 28 slices. The join should be
checked for an ID formatting problem (the IDs are 38-digit integers and lose
precision if parsed as floats).

kind, and the "paper method" bars in the current comparison figures exist only
for sa-001, sa-003, sa-009, sa-019, and sa-025 to sa-027.

## 6. Task list before any agent score can be compared to a paper method

A comparison needs three things at once: the paper's exact slices, a published
per-method number for that exact task, and our scorer computing the same
metric on the same unit. As of 2026-09-14 no task satisfies all three. Even
sa-001 scores on 25 of the paper's 123 marker genes and on a 50% spot split,
and its inputs are the unshuffled slices while the paper's Fig. 2a inputs were
randomly rotated (the two public shuffled files show a -32.3 degree rotation
for 151673; the transforms for 151675 and 151676 are not public).

## 12. What the paper says about the cell filters, and whether the code repo has them

The public code (GitHub `Yunzhi-Yan/SABench`, identical to the Zenodo zip)
contains no preprocessing script: only method wrappers, metric code, the
rotation/crop generators, and plotting notebooks that read the authors'
already-processed `*_processed.h5ad` files. The method wrappers do normalise
inside each method (for example `sc.pp.normalize_total` + `log1p` in the
spateo, GPSA, and STAligner wrappers), and the only cell filters in the code
are commented out. So the four unexplained cell sets cannot be recovered from
the repository.

The Methods text is the only description (paper lines 2036 to 2046, 2122 to
2127, 2145 to 2155):

- General rule: no QC or normalisation unless the raw-data tutorial required
  it, "however, we trimmed outlier points at the edges of certain datasets to
  ensure slices had a clean and complete shape".
- Data79 Slide-seqV2: "edge trimming was applied to reduce potential
  artifacts, followed by quality filtering, resulting in 20,835 cells". No
  parameters.
- Data231-240 (all ten AMBC slices): "we applied edge trimming and
  quality-control procedures to each slice, retaining only the right
  hemisphere region". No parameters, no statement of which replicate.

Consequences for the four non-exact slices:

| Slice | What the paper did | What we can and cannot reproduce |
| --- | --- | --- |
| Data79 Slide-seqV2 | edge trim + QC, 21,724 -> 20,835 | trim geometry and QC threshold unpublished; all beads kept |
| Stereo-seq T312 | edge trim + QC + right hemisphere, 74,466 -> 56,048 | same; all cell-type-annotated cells kept (gene set exact) |
| Xenium | right hemisphere of one of the three Fresh Frozen Mouse Brain replicates + trim/QC, -> 83,381 | replicate not stated. A sparsity fingerprint (paper 0.677751) does not discriminate: oblique hemisphere cuts on rep2 (170 deg) and rep3 (25 deg) both land within 2e-5, rep1 axis-aligned within 2.5e-4. Current file is the full rep1 section. |
| CosMx | right hemisphere of the Coronal Hemisphere sample + trim/QC, -> 48,113 | correct source is "Coronal Hemisphere Basic Data Files" on the CosMx SMI Mouse Brain FFPE dataset page (brukerspatialbiology.com); our stand-in is the hippocampus-and-cortex quarter section |

The MBRM slices (Data42-44) are the one case where "right hemisphere" plus a
published count let us reproduce the cell set exactly, because the Vizgen
sections are symmetric full coronal sections and a vertical cut at the count
matches.
