# Baselines campaign: failures and not-applicable cells

The table `baselines_failures.csv` has one row per (task, method) cell that failed at least once or is not
applicable. It is generated by `scripts/document_baseline_failures.py`; rerun that script once the campaign
finishes for the final version. A cell's status is decided by its latest attempt: it is "resolved" if a later
attempt succeeded or its `scores.json` exists.

The `genuine_method_failure` column separates failures of the method itself, which should be reported as
"failed runs" the way SABench does, from failures we caused (runner gaps, data layout) and later fixed.

## Categories

| Category | What happened | What we did | Counts as a method failure? |
|---|---|---|---|
| `not_applicable_no_shared_features` | sa-406 pairs RNA genes with H3K4me3 genomic peaks, so the slices share no feature | not submitted (listed in `not_applicable.tsv`) | not applicable |
| `not_applicable_special_task` | sa-005 (resolution recovery) has no generic per-slice layout; it needs `run_bca_resolution_recovery.py` | not run with the generic runners | not applicable |
| `runner_star_tasks` | our SANTO and STalign runners only chained consecutive sections; the 10 star tasks align every section to one reference | star mode added to both runners; all affected cells resubmitted | no |
| `duplicate_gene_names` | the Visium/Visium HD panels in sa-015 and sa-210 list 40 gene names twice, which breaks name-based gene matching | the shared gene step drops duplicates (first kept, 32,245 genes); resubmitted | no |
| `gpu_out_of_memory` | GEASO's memory grows with cells²; the large pairs (Visium HD, Slide-seq, Stereo-seq, OpenST windows, sa-010, sa-032) needed 35–105 GB | retried on A100/H100/L40S, then with `--max-obs-per-slice 20000` (fit on a subsample, apply the rigid map plus interpolated displacement to all cells; recorded in each manifest) | no if a retry succeeds; yes otherwise |
| `illegal_instruction` | STAligner's `annoy` was built for newer CPUs and dies with SIGILL on haswell nodes | STAligner restricted to icelake/sapphirerapids nodes | no |
| `cpu_out_of_memory`, `timeout` | job memory or wall-time limit hit | one retry with more memory or time | yes if the retry fails |
| `method_internal_error` | the method's own code raised an error on this input | recorded, not patched | yes |

## How to state it

"Each published method was run once per task with the settings documented in its runner. Cells where a method
raised an error, ran out of memory after one retry, or exceeded its time limit are counted as failed runs
(n = …, by method in Table S…). Cells where a method cannot apply (no shared features, sa-406; a
non-standard task layout, sa-005) are excluded. Large pairs that exceeded GPU memory for GEASO were fit on a
20,000-cell subsample per slice."
